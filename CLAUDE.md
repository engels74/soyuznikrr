# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Zondarr is a two-runtime monorepo: a Litestar/Granian Python backend (`backend/`) and a SvelteKit/Bun frontend (`frontend/`), plus a Python dev-server orchestrator (`dev_cli/`). There is no root Python project — backend commands run from `backend/`, frontend commands from `frontend/`.

## Essential Commands

Run from the repository root:

```bash
uv run dev_cli                 # Preflight + start backend :8000 and frontend :5173
uv run dev_cli --backend-only  # or --frontend-only, --skip-auth, --no-reload, --open
uv run dev_cli stop            # Kill servers tracked in .dev_cli/*.pid
bun run lint                   # prek run --all-files (whole-repo hooks)
```

`uv run dev_cli` is the intended entry point: it loads `.env`, generates/persists `SECRET_KEY` to `backend/data/.secret_key`, runs `uv sync --extra dev` / `bun install` when deps are missing, applies Alembic migrations, and wires `CORS_ORIGINS` + `PUBLIC_API_URL` + `BOOTSTRAP_TOKEN_FILE` between the two processes. Starting the servers by hand skips all of that.

Backend (from `backend/`):

```bash
uv run pytest                                   # Full suite (xdist -n auto via addopts)
uv run pytest tests/test_totp.py                # Single file
uv run pytest tests/test_totp.py::test_name     # Single test
uv run pytest -k "csrf"                         # Filtered
uv run basedpyright                             # Type check (typeCheckingMode = recommended)
uv run ruff check . && uv run ruff format .     # Lint + format
uv run alembic revision --autogenerate -m "..."  # New migration
uv run alembic upgrade head                      # Apply migrations
```

Frontend (from the repo root, or drop `--cwd frontend` when inside `frontend/`):

```bash
bun run --cwd frontend check                          # svelte-kit sync + svelte-check
bun run --cwd frontend test                           # vitest --run
bun run --cwd frontend test src/lib/api/client.test.ts  # Single file
bun run --cwd frontend build                          # Production build (svelte-adapter-bun)
bun run --cwd frontend generate:api                   # Regenerate OpenAPI types — backend must be live on :8000
```

CI (`.github/workflows/code-quality.yml`) runs exactly three gates: `prek --all-files --hook-stage manual`, `basedpyright` + `svelte-check`, and both test suites. Match that sequence before declaring work done.

## Architecture Overview

**Backend layering** (`backend/src/zondarr/`): `api/` Litestar `Controller` classes → `services/` business logic → `repositories/` data access → `models/` SQLAlchemy. Controllers never touch `AsyncSession` directly; each controller module declares its own `provide_*` DI factories and attaches them via `Controller.dependencies`. Request/response types are `msgspec.Struct` classes centralized in `api/schemas.py`.

`app.py::create_app()` is the single composition root: it calls `register_all_providers()`, loads `Settings`, assembles the `route_handlers` list (static controllers plus any contributed by providers), and registers lifespans (DB pool, bootstrap token, log buffer, background tasks) and the domain-exception handler map. `core/database.py::provide_db_session` supplies a session that commits on success and rolls back on exception — the transaction boundary is the request.

**Provider registry** (`media/registry.py`): a singleton keyed by `server_type`. Each provider (`media/providers/plex/`, `media/providers/jellyfin/`) exports a `ProviderDescriptor` declaring metadata, client class, admin auth, join flow, optional route handlers, and OAuth support. The registry also resolves effective credentials — env vars declared in `ProviderMetadata.env_url_var`/`env_api_key_var` override the DB value; otherwise the stored API key is decrypted.

**Frontend request flow**: the browser talks to SvelteKit, which proxies everything under `/api/*` to the backend via `src/routes/api/[...path]/+server.ts` (streams `text/event-stream`, buffers everything else). `src/hooks.server.ts` reads the `zondarr_access_token` cookie, refreshes it against `/api/auth/refresh`, populates `event.locals.user`, and enforces the onboarding/login redirects. `$lib/api/client.ts` is the typed openapi-fetch client with a 401 auto-refresh middleware.

**Wizard interaction types** are registered twice, once per runtime: backend `services/interactions/registry.py` (exhaustive `match` guarded by `assert_never`) and frontend `lib/components/wizard/interactions/register-defaults.ts`. Both must gain the new type or the feature is half-wired.

## Common Change Workflows

**Add a backend endpoint**
1. Add request/response `msgspec.Struct`s to `api/schemas.py`.
2. Add the handler to the relevant `Controller` in `api/` (controller-level `path` is the full `/api/v1/...` prefix), or create a new controller and append it to the `route_handlers` list in `app.py::create_app()`.
3. If the endpoint mutates state and is hit before CSRF origin setup, add its path to `_CSRF_EXCLUDE_PATHS_BASE` in `core/csrf.py`.
4. Regenerate frontend types with `generate:api`, then add a wrapper in `$lib/api/client.ts`.
5. Add a test under `backend/tests/`.

**Add a model or change the schema**
1. Define the model in `models/`, then export it from `models/__init__.py` — Alembic autogenerate and the test-schema builder both rely on that import.
2. Add the new table name to `_TRUNCATE_ORDER` in `backend/tests/conftest.py`, children before parents.
3. `uv run alembic revision --autogenerate -m "..."` then `uv run alembic upgrade head`.

**Add a media server provider**
1. Create `media/providers/<name>/` with a client implementing `MediaClient` plus a `ProviderDescriptor` class (see `media/providers/plex/__init__.py`).
2. Register it in `media/providers/__init__.py::register_all_providers()`.
3. Add its env var names to `.env.example` and an OpenAPI `Tag` in `app.py::_create_openapi_config()` if it contributes routes.

**Add a wizard interaction type**
1. Add the value to `InteractionType` in `models/wizard.py` and a handler case in `services/interactions/registry.py::_create_handler()` (`assert_never` will fail the type check otherwise).
2. Add the Zod schema to `$lib/schemas/wizard.ts`, the interaction + config-editor components under `lib/components/wizard/interactions/`, and a `registerInteractionType()` call in `register-defaults.ts`.

## Implementation Decisions

| Situation | Preferred approach | Avoid |
| --- | --- | --- |
| Backend serialization/validation | `msgspec.Struct` (`kw_only=True, forbid_unknown_fields=True` for requests) | Pydantic — present only as a transitive `jellyfin-sdk` dep and warning-filtered in `pyproject.toml` |
| Reading/writing entities | A `Repository` subclass from `repositories/` | Building `select()` statements inside controllers or services |
| Creating a media client | `registry.create_client_for_server(server)` | Instantiating `PlexClient`/`JellyfinClient` directly — that bypasses env-var overrides and API-key decryption |
| Frontend API call | A wrapper in `$lib/api/client.ts` | Ad-hoc `fetch` in components; raw `fetch` in `client.ts` is reserved for endpoints absent from the OpenAPI spec |
| Styling | UnoCSS utilities plus the `cr-*` tokens from `uno.config.ts` / `app.css` | Tailwind — `tailwind.config.js` is an empty stub kept only for the shadcn-svelte CLI |
| Cross-component reactive state | `.svelte.ts` rune modules in `$lib/stores/` | Svelte 4 `writable`/`readable` stores |

## Repository Conventions

- Frontend files are kebab-case. Tests that exercise runes or render components use `*.svelte.test.ts`; plain-module tests use `*.test.ts`. Both patterns are in `vite.config.ts`'s `include`.
- Backend code targets Python 3.14: PEP 695 generics (`class Repository[T: Base]`), no `from __future__ import annotations`, positional-only `/` parameters on registry and repository lookups.
- Biome formats the frontend with tabs, single quotes, no trailing commas, 100-col width; ruff formats the backend at 88 cols with double quotes. Both run via prek — do not reformat by hand.
- Commits must be Conventional Commits (`conventional-pre-commit` on the `commit-msg` stage), and the `no-commit-to-branch` hook blocks direct commits to `main` once `prek install` has run. Work on a branch.

## Testing and Validation

- `backend/tests/` holds example-based tests; `backend/tests/property/` holds Hypothesis property tests (`test_*_props.py`). `pyproject.toml` sets `asyncio_mode = "auto"`, so async tests need no decorator.
- `backend/tests/conftest.py` registers four Hypothesis profiles and unconditionally loads `default` (15 examples, shrinking disabled). To investigate a failing property test, temporarily switch that `load_profile` call to `"debug"`.
- Database fixtures are in-memory SQLite. Use the `db` fixture (`TestDB.clean()`) inside `@given` tests to truncate between examples instead of rebuilding the engine; use `session`/`test_engine` for ordinary tests.
- Frontend tests are colocated with their source under `frontend/src/`, run in jsdom with `@testing-library/svelte`, and are set up by `frontend/vitest-setup.ts`.
- The prek pre-push stage runs `svelte-check`, `basedpyright`, and both test suites; pre-commit only runs formatters, Biome, and the secret scanners.

## Critical Gotchas

- **`SECRET_KEY` is a data-encryption key, not just a signing key.** `services/api_key_encryption.py` and `services/totp_encryption.py` derive Fernet keys from it via HKDF. Rotating it makes every stored media-server API key and TOTP secret undecryptable. Use the persisted `backend/data/.secret_key` in development rather than generating a new one.
- **The backend must run with a single Granian worker on SQLite.** `dev_cli/runner.py` pins `--workers 1`; more workers cause write-lock contention. Engine setup in `core/database.py` uses `NullPool` + WAL for the same reason.
- **CSRF denies by default in production.** `core/csrf.py` rejects mutating browser requests when no trusted origin is configured (debug mode only warns). New mutating endpoints reachable before setup completes need an entry in `_CSRF_EXCLUDE_PATHS_BASE` or `CSRF_EXCLUDE_PREFIXES`.
- **`types.d.ts` drifts.** `$lib/api/client.ts` already carries hand-written interfaces for endpoints added after the last generation. Prefer running `generate:api` over adding another manual override.
- **Backend `.venv` lives in `backend/`.** `basedpyright` is configured with `venvPath = "."` relative to `backend/`, so type-checking from the repo root will not resolve imports.
